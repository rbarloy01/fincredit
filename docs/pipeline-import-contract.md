# FINmonitor Pipeline Import Contract

The production Vercel app accepts Python FINmonitor pipeline output through:

```text
POST /api/pipeline/import
```

The endpoint is manager-only and requires a Supabase access token:

```bash
curl -X POST "$APP_URL/api/pipeline/import" \
  -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  --data-binary @outputs/financial_monitor/financial_monitor_pipeline.crm.json
```

Use `{"dryRun":true,"payload":{...}}` to validate shape without writing rows.

## Safety Rule

Imported financial values are written to `extraction_review_items` with
`status = 'pending'`. They do not update `financial_statements`, mapped metrics,
or covenant compliance until a manager approves them through:

```text
POST /api/review-items/approve
```

That preserves the existing review gate: extraction/import proposes values;
approval promotes values.

## Accepted Input

The endpoint expects the sidecar shape generated by the Python workspace:

```json
{
  "concepts": [
    {
      "client": "Ventus",
      "period": "2026-04-30",
      "statement": "BG",
      "filename": "260430 - BG - Ventus.pdf",
      "raw_label": "TOTAL ACTIVO",
      "value": 123,
      "concept": "total_activo",
      "mapping_confidence": 1,
      "mapping_status": "approved",
      "source_ref": "/path/to/source.pdf"
    }
  ]
}
```

Rows are skipped when the client does not already exist in the app, the period is
missing, or the value is not numeric.
